# r35 STEP4月別資金推移パネル 検証記録

## 範囲とデータ対応

対象はSTEP4の表示、印刷用CSS、月別CSVのみ。税額計算、制度判定、月配分、中間・確定納付・還付、保存形式は変更していない。

| パネルの値 | 既存の正本・変換 |
| --- | --- |
| 対象月 | `cashflow-engine.js` の `engine.rows[].month` と対象期。間の0円月も連続で保持 |
| A/Bの納付・還付 | 完成結果は `engine.rows[].baseTax` / `changedTax`。部分結果では案別に確認済みのイベントを保持するが、B−Aの税金込み差額を照合できない場合はパネル全体を不足理由付きで未算定にする |
| B−Aの日常差 | 同じ月の `engine.rows[].sales + purchase` |
| Aの日常増減（食品1％比較） | STEP3現行税率側の売上・仕入税額を既存の回収・支払月ずれで配置した表示用参考額。CSVを選び、現在行と元CSVの区分・税率・金額・期間・日付状態が安全に照合できた側はCSV月別構成、できない側は対象日数均等。実際の営業収支ではない |
| Aの日常増減（方式比較） | 両案に共通する取引を相殺した基準0円。実際の営業収支0円ではない |
| Bの日常増減 | Aの日常増減 + 既存エンジンの取引差。STEP4の税額・配分エンジンは再実行しない |
| 月次・累積差額の照合 | `engine.rows[].net` / `cumulative` と、パネルの B−A を円単位で全月照合。完成結果の不一致は内部エラー。部分結果で既知イベントと未確定税額が照合不能なら入力待ちの未算定 |
| 未確認 | `engine.status` / `reasons` と入力の確認状態を表示。未知イベントの金額はCSVでも空欄 |

期間・月ずれ・現行側の税額が不足してAの日常増減を構成できない場合、0円で補わずパネルを未算定とする。部分試算で確認済みの案別税イベントが既存の取引差と整合しない場合も、完成した線として描かない。この制限は税金込みの最終資金差額を未算定のまま保つため。

## r35表示・状態補正（2026-09-27）

- 灰色帯はAを順方向、Bを最終点から「縦→横」で逆走する外周へ修正。全月同額の面積0、途中差、最終月継続、途中交差を、SVGの実座標点列との一致で自動検証した。
- 部分試算の案別既知イベントが既存STEP4の未確定差額と異なる場合、内部エラーではなくエンジンの `reasons` を用いる「未算定：不足条件」にした。真の完成結果の不一致と、エンジン自身の累計不整合は内部エラーのまま停止する。片案のイベントを0円と推測して表示しない。
- 確定納付・還付の予定月は、差引Qが正・負で実際に必要な側だけ警告する。Q=0は両方不要。CSV月別構成はA表示専用に元グループと現行行の区分・税率・金額・期間・日付不明件数を照合し、照合できない側は日数均等に戻す。B−Aの既存配分は不変更。両側の配分前提を別々に注記する。
- 同座標・同種・同額のA/Bイベントは「A・B共通」マーカー1個にし、表には両案の実額を残す。方式比較の0円日常行を隠し、375〜390pxの左見出しを140pxに縮めた。印刷表を8→10px、表の補足を7→9pxへ拡大した。
- `npm test` 614件成功（元609＋追加5）、`npm run build` と `git diff --check` 成功（改行コード変換予告のみ）。Chrome/Playwrightの匿名HTTP環境で13項目成功、pageerror 0。通常例、11回共通中間、部分試算、CSV月別構成の表示用例、375/390px、保存再読込、月別CSV、A4印刷を確認。A4 PDFは4ページで、前後半パネルの列欠けはなく、表・補足の拡大を画像で確認した。
- 実顧客CSVそのものの月別再構成、職員による読みやすさ評価、実プリンター出力は未実施。ChromeのCSV月別構成は匿名の元グループを本番の表示関数へ渡して確認したもので、CSVファイル選択操作までは再実行していない。

## 実行方法と残る制限

- `npm test`、`npm run build`、`git diff --check`
- Chrome: `PLAYWRIGHT_MODULE` に利用可能なPlaywrightの場所を設定し、`node scripts/step4-panel-browser-smoke.cjs`。出力先は任意で `STEP4_PANEL_RESULTS_DIR`（リポジトリ外）
- 表示用A案日常増減はSTEP3の売上・仕入税額からの参考配分であり、安全なCSV照合ができた場合も実際の月別入出金や全社資金残高ではない。方式比較も共通営業収支を表示しない。
- 中間納付など案ごとに既知のイベントが非対称で、既存部分試算のB−Aに整合しない場合、未知額を推測で相殺せず入力待ちを示す。
- 旧任意スモーク `scripts/cashflow-browser-smoke.js` は現行のSTEP3に必要な入力を満たさない旧シードのため、パネル到達前に停止した。今回のChrome検証は現行入力を満たす匿名シードを持つ新スクリプトで実施した。
