# r35 STEP4月別資金推移パネル 検証記録

## 範囲とデータ対応

対象はSTEP4の表示、印刷用CSS、月別CSVのみ。税額計算、制度判定、月配分、中間・確定納付・還付、保存形式は変更していない。

| パネルの値 | 既存の正本・変換 |
| --- | --- |
| 対象月 | `cashflow-engine.js` の `engine.rows[].month` と対象期。間の0円月も連続で保持 |
| A/Bの納付・還付 | 完成結果は `engine.rows[].baseTax` / `changedTax`。部分結果は入力で確認済みの同額イベントだけを表示 |
| B−Aの日常差 | 同じ月の `engine.rows[].sales + purchase` |
| Aの日常増減（食品1％比較） | STEP3現行税率側の売上・仕入税額を、対象期の日数と既存の回収・支払月ずれで配分した表示用参考額。実際の営業収支ではない |
| Aの日常増減（方式比較） | 両案に共通する取引を相殺した基準0円。実際の営業収支0円ではない |
| Bの日常増減 | Aの日常増減 + 既存エンジンの取引差。STEP4の税額・配分エンジンは再実行しない |
| 月次・累積差額の照合 | `engine.rows[].net` / `cumulative` と、パネルの B−A を円単位で全月照合。不一致時はグラフを停止 |
| 未確認 | `engine.status` / `reasons` と入力の確認状態を表示。未知イベントの金額はCSVでも空欄 |

期間・月ずれ・現行側の税額が不足してAの日常増減を構成できない場合、0円で補わずパネルを未算定とする。部分試算で確認済みの案別税イベントが既存の取引差と整合しない場合も、完成した線として描かない。この制限は税金込みの最終資金差額を未算定のまま保つため。

## 実行方法と残る制限

- `npm test`、`npm run build`、`git diff --check`
- Chrome: `PLAYWRIGHT_MODULE` に利用可能なPlaywrightの場所を設定し、`node scripts/step4-panel-browser-smoke.cjs`。出力先は任意で `STEP4_PANEL_RESULTS_DIR`（リポジトリ外）
- 表示用A案日常増減は年税額側からの日数均等配分であり、実際の月別元帳や全社資金残高を示さない。方式比較も共通営業収支を表示しない。
- 中間納付など案ごとに既知のイベントが非対称で、既存部分試算のB−Aに整合しない場合、未知額を推測で相殺せずパネルを停止する。
- 旧任意スモーク `scripts/cashflow-browser-smoke.js` は現行のSTEP3に必要な入力を満たさない旧シードのため、パネル到達前に停止した。今回のChrome検証は現行入力を満たす匿名シードを持つ新スクリプトで実施した。
