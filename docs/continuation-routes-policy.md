## 接続と状態

`tax-obligation.js` は税額を別計算しない。対象期間、届出の事実・予定、納税義務、課税選択・登録の取引取込期間と継続制限を返す。UIは `taxableWindow` を同じ税額エンジンへ渡す。`maintain` は0円の第5方式ではない。`status` は `available / planned / unknown / unavailable`。未確認の免税維持や適用不可の課税選択を確定的な推奨に使わない。

`resolveReferenceFacts` は履歴の開始・終了日が法定参照期間と一致した資料だけ利用する。現在期売上は2年後の基準期間予測には使えるが、翌期の基準期間や特定期間へ無条件に流用しない。年間売上から前年上半期を自動生成しない。予測は `source:'forecast'` のまま維持する。

`buildProjectionPeriods` は4期を基本とし、食品シナリオでは措置終了後に始まる期まで最小延長する。最長16期。短期の初年度後は1年周期を仮定するため、決算期変更等の確定資料がある場合は `futurePeriods` を渡す。16期に達しても終了後を含まない場合、完成した比較と表示しない。

`optimizeFourPeriodRoutes` は算定額null・空欄・非有限を候補から除く。税額未算定と制度上の未確認は `periodAssessments` で別に保持する。予定を含む最安経路は `selectionStatus:'planned'`、提出予定を含まない経路は `bestConfirmedRoute` と `confirmedCumulative` で区別する。成立前の例外を含む経路は `policyScenario:true`。既存の現行法4期経路は明示された `foodDiscontinuanceInput` がない限り例外を使わない。

## 制限・再開条件

- 資産取得による免税復帰制限は、事実が未確認なら復帰可否を確定しない。課税選択した場合の当期計算は継続できる。
- 調整対象固定資産の仕入税額調整、棚卸資産の課税移行時調整、国外事業者、新設・合併等の詳細計算を自動で完結させない。他の納税義務は実際の履歴に基づく補足が必要。
- 日付だけで届出済み又は登録済みと認定しない。`filed` と `planned` を維持する。実際の提出・登録は行わない。
- 税額に影響する対象期間・基準売上の参照修正を含む。保存案件も最新入力から再試算が必要。

## 最終レビューでの共用修正

- 対象期の納税義務確認は開始・終了日に結び付け、期間変更時に別期へ付け替えない。方式表と免税経路で既入力の基準期間・特定期間・給与額を共用する。
- 同じ正式期間CSVから該当半期を日別又は月境界の実額で取得できる場合、将来の特定期間判定に再利用する。年額から上半期を創作しない。
- 免税年の売上は受取対価のまま履歴へ渡す。課税年は税抜基礎、期中登録年は登録前対価と登録後税抜額を結合。義務状態不明の年は、いずれかの基礎を確定資料として流用しない。
- 高額資産の既存入力と将来設備投資を、方式別制限・免税復帰へ共用する。将来の設備合計だけで法定単位額を満たす取得済み事実とは認定せず、該当する期間の可否を未確認にする。調整対象固定資産の現行要件も、一般課税を仮定した課税選択経路へ反映する。
- `eligible:true`と明示unknownが衝突した場合はunknownを優先する。算定null・計算状態unknown・選択ineligible/unknownを最適化の0円又は利用可能候補へ変換しない。
- 移行棚卸・固定資産の詳細調整額は未算入の概算と画面・共通出力へ明記。現行要件が不明なのではなく、原税率・数量・保有・取得/申告履歴等の案件資料が必要。[分類記録](continuation-final-review.md)参照。
