# 期中登録の対象取引額とCSV日付実額

2026-10-24 JST / 2026-10-23 UTC。これは税率・届出の新しい算式ではなく、既に判定した課税対象取引期間へ、同じ正式資料の取引額を切り出す実装である。前回の一律日数概算に実額優先が欠けていた点は、制度未確定ではなく受入③・④内の仕様確定未実装（c）として修正した。

## データと優先順

`journal-csv.js` の `analysis.dailyGroups` は、課税区分・元税率・事業区分・用途・控除割合・取引日・符号付き合計・通常/調整だけを日別集計する。科目名、摘要、取引先、伝票番号、CSV原文は出力しない。既存 `monthlyGroups` は変更しない。

`taxable-window-rows.js` の `slice({rows,actualOnePercentEntries,period,window,csvSource,currentSourceId,dailyGroups,monthlyGroups,dateUnknownCount,knownZeros})` は、共有CSVと同一のID、正式期間、全月網羅、現在行の分類・年間額が日別/月別額と一致するときだけ実額を返す。

1. 日別集計があれば、登録日（境界日を含む）以後を直接集計する。
2. 日別を持たない旧保存では、対象取引期間の開始・終了が月の境界又は元資料の端に一致するときだけ月別実額を使う。
3. 月途中の境界・日付不明・別資料・手修正後の不一致・未対応輸入等は `ready:false` と理由を返す。呼出側は理由付きの概算又は未算定を維持し、日次実額と呼ばない。

`rows` と明示1％の `actualOnePercentEntries` は別々に返す。明示1％を8％の通常行へ重複追加しない。区分11の返還は入力方向を維持し、元CSVの符号を一度だけ反転する。年間差引0の仕入に登録後の正負取引がある場合も、その対象期間額を消さない。

8％行の「うち食品」が全額なら、その分類グループの対象日額を使用する。一部だけ食品で日別食品情報がなければ、同じ課税区分グループの構成を代理にした額と明示する。食品の日次実額とは呼ばない。`foodPeriodAmountsById` は、切出後の行のうち食品政策期間内に属する金額を算定済みであり、呼出側で再び対象期間割合を掛けない。

## 独立検算と試験

1〜6月の税込売上990,000円/仕入495,000円、7月1日の売上110,000円/仕入55,000円、7月1日登録の例では、登録後の売上税10,000円−仕入税5,000円＝一般課税5,000円。全期間額を184/366で配分しない。既存申告書計算へ切出した整数円行を渡し、この5,000円を検証した。

`node --test tests/taxable-window-rows.test.js`：10件成功。匿名性、日/月境界、季節性、同一資料/現在行の照合、部分食品代理、食品政策期間の再按分防止、明示1％サイドカー、元税率返品、差引0/負額、未知日付・不正値・未対応輸入を検証。

登録前だけの未確認返品を0円行として残して登録後を停止しない回帰も追加。旧保存に日別データがない時の移行を含め、最終全体結果は統合記録を参照。UI・保存復元・ブラウザの接続確認は統合担当の記録を参照する。本モジュールは入力状態や元CSVを変更せず、税額を独自計算しない。
