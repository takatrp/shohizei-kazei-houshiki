## 再現と変更

開始時は、内部 `calculateSimplifiedTax` が総売上税額の負号を保持する一方、食品同額控除を非負へ丸めるため、全額食品の純返品を入力した内部呼出しで相殺されなかった。一般の行入力・CSVの純負額バケットには既存エラーがあり、この内部経路を公開画面で常に誤計算する不具合とは扱わない。

`calculateSimplifiedTax` と2割・3割の共通食品処理は、食品の符号付き税額を保持する。食品以外の売上・売上高が負になる簡易・75％判定は `amount:null` と不足理由を返し、0円扱いにしない。一般課税用の取引税額は独立に返す。`tax-return-engine.js` の現行申告書計算の下限・丸めは一律に外していない。

新しい `sales-scenario.js` は元の税込行を計算源に使い、通常の正の8％食品を予測し、区分11の返還・負額調整を元税率のまま計算する。区分11は返還方向への反転を一度だけ行い、負入力による返還取消の既存意味を維持する。明示1％CSV実績は8％予測に混ぜず一度だけ加算する。原取引が不明な1％調整は未算定理由を返す。行・原CSV・摘要を新たに保存又は送信しない。

`aggregateTaxRows` の既存 `fields` は旧保存互換の差引内数を維持し、予測可能な通常取引用の `forecastFoodFields` を別に返す。`aggregateScenarioPurchases` は `foodPeriodAmount(row,foodValue)` があればその対象期間額を優先し、期間割合を二重適用しない。旧8％の負仕入を予測1％へ換算する処理は改めた。

## 独立検算

- 税抜食品売上100万円・元1％返品150万円: 売上税額 −5,000円、食品同額控除 −5,000円、簡易・2割・3割の食品差額0円。
- 税込通常食品216,000円を税抜価格据置で1％予測し、元8％返品108,000円がある場合: 新通常取引202,000円（税2,000円）、返品 −108,000円（税 −8,000円）、税込純額94,000円、取引税額 −6,000円。これを純食品108,000円から1％予測する計算は採用しない。
- Q&A問3-7の食品2,500万円・その他第2種800万円・第4種200万円（税抜）: 食品を除いた第2種割合80％、その他売上税額100万円に80％控除、簡易の食品以外差額20万円。

## 検証と残る制限

専用 `tests/food-signed-returns.test.js`、`tests/sales-scenario.test.js` は売上のみ・部分返品・返品超過・年間相殺0・8％/1％/10％/複数事業・開始/終了境界・明示実績の重複防止・月別callbackの二重適用防止を検証する。既存 `food-defaults` の区分11正負入力期待値は維持した。`tax-entry-rows.test.js` の旧8％負仕入の期待値1件だけは、上記元税率根拠に基づき101,000円/税1,000円から94,000円/税−6,000円へ変更した。

担当変更後の全体実行は871テスト成功・失敗0、`npm run build` と `git diff --check` 成功（他担当の並行変更を含む途中記録。最終記録は親の統合検証を優先）。実ブラウザ操作はこの担当では未実施。

UI行入力・CSVの純負額停止を全面解除していない。元税率・元課税状況の情報が足りない返品、食品以外が純負額となる簡易等、正式様式による食品特例の申告段階端数処理は未確認/未算定を維持する。正式法令・様式又は対象取引の元資料が確定した後に、その範囲の個別計算を追加検証して再開する。既存税額を引き継ぐ案件は再試算が必要。
