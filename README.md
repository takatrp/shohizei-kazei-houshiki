# 消費税課税方式検討ツール（所内での一次試算用）

本則課税、簡易課税、2割特例、3割特例を概算比較する所内向け一次試算ツールです。担当者が資料を確認して一次検討し、判断に迷う点を整理して相談するための参考値であり、申告判断や確定提案を代替するものではありません。

## 構成

- `index.html`: 入力・表示・保存・コピー・CSV・印刷
- `tax-engine.js`: DOMに依存しない計算・判定関数
- `tax-return-engine.js`: 現行制度の本則課税・簡易課税・特例の申告書段階の整数円計算
- `switch-decision.js`: 顧客側の追加負担、所内採算、顧客用出力の分離
- `journal-csv.js`: DOMに依存しないTKC仕訳帳CSVの解析・集計関数
- `tax-entry-rows.js`: 課税区分別の行モデルと、既存計算欄への純粋な集計アダプター
- `tax-entry-csv.js`: 補正・除外後のCSV集計から課税区分別の確認行を作るアダプター
- `cashflow-adapter.js`: STEP3の同一方式・同一入力の税額と税込差額をSTEP4用の月別差額へ接続
- `cashflow-engine.js`: 月別入出金、中間納付・確定納付・還付、累積資金差額の純粋計算
- `release-history.js`: 更新履歴、版数、更新日、制度基準日
- `tests/*.test.js`: Node.js標準テスト

ビルド工程や外部APIは使用せず、GitHub PagesとローカルHTMLで動作します。Google Analyticsには通常のページ閲覧以外の入力値・計算値を送信しません。

## r31・STEP4「資金繰りへの影響」

食品1％の未施行政策試算では、税額比較（画面上のSTEP3）の次に「資金繰りへの影響」（STEP4）へ進めます。内部画面IDは旧保存値との互換のため1→2→4→5で、画面上は4段階です。STEP4の税額はSTEP3と同じ方式・同じ現在入力の現行税率額／食品1％額を使い、税額計算・制度判定を別実装しません。売上の入金差、仕入の支払差、両案別の中間納付と確定納付・還付を月別に示し、月末累積差、最大の一時資金減少、精算後差額を確認できます。これは一課税期間の対象取引と当期税金予定を比較する参考試算で、将来の全社資金繰り予測ではありません。

中間納付が未確認なら税金を0円として完成扱いにせず、取引差だけの部分試算と「税金込み未算定」を表示します。中間納付額を入力した場合は各案の当期税額から既納予定額を差し引いた残額のみを確定納付し、超過額は還付予定へ置きます。未納、過年度分、翌期新規取引は対象外です。売上・仕入の決済ずれは各0～2か月、現行率と食品1％率の価格前提はSTEP3と共通です。元資料の期間・全月網羅を確認できたCSVは補正・除外後の匿名化月別構成比を選べます。日付不明、期間未確認、手修正で構成が合わない場合は対象日数による均等配分へ戻し、理由を残します。CSVなしの手入力でも利用できます。

STEP4を表示中のコピー・CSV・印刷は専用の資金差額と前提を出力します。従来の方式比較・顧客向け帳票とは別で、元CSVの個別科目・摘要や顧客名は取り込みません。手順とCF01～CF30の検証範囲は [STEP4検証記録](docs/cashflow-step4-verification.md) を参照してください。自動テストは `npm test`、静的検証は `npm run build` です。任意の実ブラウザー確認は、ローカルにPlaywrightとChromeがある場合だけ `PLAYWRIGHT_MODULE` と `CHROME_PATH` を設定して `node scripts/cashflow-browser-smoke.js <出力先>` を実行できます。実顧客CSVをこのスモークテストへ渡さないでください。

## r30・現行制度の申告書計算

手入力・TKC仕訳帳CSVのどちらも、現在表示中の課税区分別行を税額の正本にします。課税区分1の売上と11の売上返還等を分け、本則課税では付表2-3→付表1-3→第一表の順に計算します。簡易課税・2割・3割特例も現行制度の申告書段階で端数処理します。比較・4期累計・コピー・CSV・印刷は同じ端数処理後の結果を使います。比較額は中間納付を差し引く前の当期税額です。

CSV集計と申告書の仕入額が異なる場合は、取込欄の「申告書との照合調整」で差額の符号と根拠を確認して明示入力してください。摘要による自動除外はしません。金額の無変更フォーカス移動ではCSV由来を変更せず、行の追加・削除・金額変更では現在行から再計算します。CSV明細の仮定・明示的な仮除外があっても、残る行から計算可能なら申告書段階の端数処理後の額を「参考」として比較・4期累計・出力へ使い、厳密な申告書再現は未完了と示します。仮除外部分の税額影響は未算定で、件数・読取可能額・金額不明件数を前提に残します。未処理明細・未対応コードや必須情報不足など計算不能な場合は「未算定＋理由」とし、旧概算額へ自動的に戻しません。対象期間外のCSV実績は参考前提を表示します。食品1％政策試算は従来の概算経路です。実申告には元帳、用途区分、届出、個別調整、中間納付等の確認が必要です。

匿名化した固定集計値と本番CSV解析関数を通す回帰結果は [r30検証記録](docs/return-golden-verification.md) を参照してください。実顧客のPDF・CSVと個別仕訳はリポジトリに含めません。

原CSVを手元で再照合する場合のみ、`node scripts/verify-local-return-golden.js --csv <手元のCSV> --adjust10 <確認済みの符号付き調整額> --exclude <確認済みのCSVレコード番号:借方または貸方>` を実行できます。除外を複数指定する場合は `--exclude` を繰り返します。指定した原CSVや個別仕訳はスクリプトから書き出さず、集計欄の差額だけを標準出力へ表示します。帳簿・申告書で除外根拠を確認せずに引数を指定しないでください。

新しい金額画面は、TKC課税区分1・11・3・5・6・7・52・62・72の行入力です。番号を直接入力し、Enterで必要な列だけ進めます。金額は税込、食品1％対象額は軽8％行の内数です。行から従来の計算入力へ集計し、食品1％・将来期では元の仕入行から税額総額と用途別内訳を同じ条件で再計算します。CSV反映時は課税区分別の集計行を表示し、元データの仮定・補正・除外と明示1％実績は別情報として残します。CSVのゼロ集計で課税区分を復元できないものは推測しません。

行の金額は入力中とCSV反映直後から3桁区切りで表示します。課税区分・事業区分の候補は番号と名称・業種例を1行で示し、税率候補は「10％」「軽減8％」と表示します。不要なセルは「—」の非入力表示です。免税事業者等仕入の控除割合候補には対応時期を示します。手入力は対象期との重なり、日付の分かるCSVは元取引日との整合を確認します。矛盾が残る本則税額と4期累計は未算定とし、理由を画面・出力へ残します。進行ボタンと対象期の要約はスクロール中も画面上部に表示します。

食品1％試算の「期間別金額の扱い」は、年額・期間額の日数均等按分を原則として初期・リセット時に選択します。1％対象期間分を直接入力する方法も引き続き選べ、保存済みの選択は維持します。

免税事業者等からの仕入の値引き・返品等は、概算ではCSVに記載された同じ課税区分・税率・控除割合の仕入額から貸借の符号どおり差し引きます。個別の元取引を入力し直す必要はありません。件数・取引絶対額と「元取引の時期・税率は照合していない」という前提を画面・通常コピー・CSV・印刷に残し、参考試算として扱います。通常取引の控除割合と取引日・対象期の矛盾、および明示1％取引の確認事項は従来どおり区別します。元CSVの個別情報は帳票へ転記しません。

最初の画面の「比較・試算する方式（複数選択可）」で一般課税・簡易課税・2割特例・3割特例を選べます。「すべて選択」も使えます。新規入力・リセット時は全方式が未選択で、1つ以上選ぶまで手入力画面への進行とCSV反映を止めます。初期状態は通常の案内とし、未選択で進もうとしたときに警告を表示します。一般課税だけを選ぶと、簡易課税の事業区分や届出、特例だけの判定条件を入力しなくても比較へ進めます。CSVの事業区分未確認売上も、簡易課税を比較しない場合は区分を推測せず金額を取り込みます。未選択方式は当期の比較表・現行税率との差額・4期経路・通常出力に含めず、選択内容を帳票の前提に記載します。この選択は比較対象の絞り込みであり、現在の申告方式や制度上の適用可否を変更しません。端末保存を有効にした場合は選択内容も復元します。

## r29の修正

- F01：食品1％試算の本則課税では、税込仕入行・食品内数・価格前提から総額と3用途の税額を同時に算定します。復元不能な旧形式の食品用途別税額は推定せず未算定にします。
- F02：CSV反映は入力金額の置換が標準です。既存入力がある場合は現在・今回CSV・反映後の金額を確認し、手入力行を残す場合だけ「追加」を選びます。再反映で旧CSV行を重複加算しません。
- F03：4期試算の免税事業者等仕入は元の行金額・税率・用途を使い、将来各期の控除割合で再計算します。食品1％を含む4期経路は引き続き未対応です。
- F04：手動割合と対象期間、CSV元取引日と元割合を照合します。矛盾・元取引未確認は本則と影響する4期経路を止め、他方式の単独参考値は維持します。過年度CSVを将来期の参考に使う場合は、元資料の割合と試算対象期の割合を区別します。
- 期待値と検証の詳細は [検証記録](docs/review-fixes-20260923.md) を参照してください。ブラウザー・PDFの実確認は自動テストとは別に扱います。

食品1％試算の将来の食品売上・仕入価格は、初期値をいずれも「税抜価格据置」とし、変更する場合だけ任意の折りたたみを開きます。閉じた状態でも現在の前提を表示し、結果の計算過程・前提にも残します。食品区分の注意文と行入力表の課税区分名は1行表示にし、狭い画面では必要に応じて横スクロール・省略表示で扱います。

端末保存は行の順序・入力元（手入力／CSV／CSV後の手修正）・空欄と明示0円・控除割合を保持します。旧形式の保存値は行へ無理に変換せず、従来の集計入力画面で開きます。行入力時に旧金額欄を同時編集できないようにしています。顧客向け印刷に所内用のTKC番号や元CSV個別情報は追加しません。

## r28の主な対応

- F01〜F05修正では、当期と4期の簡易課税届出・継続制限判定を共通化し、本則の仮計算額と当期の選択可否を分離しました。課税期間が空欄・逆転等の場合は全方式の比較と4期累計を未算定にします。
- 免税事業者等仕入の「未確認」は入力済み金額で概算を続けつつ参考表示に残します。CSVでは元の取引日範囲と補正・除外後の有効明細範囲を区別し、対象期間と異なる実績の流用・手修正を画面と帳票へ表示します。売上・返品が相殺された有効明細の0円は未入力と区別します。元CSV全文や個別明細は保存・帳票へ追加しません。
- F01〜F05と第2次修正の検証記録は `docs/r28-fix-verification.md` を参照してください。詳細試算は入力欄の表示切替であり、保存済みの届出・継続状態に基づく方式選択可否を変えません。現在簡易課税で変更条件が未確認の本則は、税額を試算できても選択可否未確認とし、最有利候補へ含めません。
- 中心となる「方式別比較」を強調し、方式・適用状態・金額を大きく整列しました。食品1％モードでは現行税率・1％試算・差額を横に配置し、増減は符号・文字・色で表示。長い計算方法と確認事項は各方式の下へ移し、計算過程もその場で開けます。
- 上部の「印刷」、表の「比較表を印刷」、ブラウザの印刷操作は、方式別比較と必要な前提・未確認事項をまとめたA4縦の専用帳票を使用します。食品1％の現行税率・差額も同じ金額で印刷します。印刷のための再計算エンジンは追加しません。
- 原則1ページですが、7ptを実務上の最小文字サイズ目標とし、長い注記がある場合は2ページ以上を許容します。毎回等倍から測定し、縮小後の実寸を最大4回再確認します。注記の省略・切り捨てはしません。A4縦・余白10mm・倍率100％・ヘッダー／フッターなしで印刷プレビューのページ数、末尾、可読性を確認してください。画面に出るページ数は計測上の見込みであり、PDFの実ページ数ではありません。
- 第3次の印刷調整では、同じ確認理由が方式・現行税率・食品1％・未確認欄で重複する場合に帳票内で集約し、印刷専用のセル余白・行間・見出し間隔を圧縮しました。7pt下限と長文時の複数ページ許容は維持しています。印刷時は背景グラフィックを有効にした場合も `html` と `body` を白に指定します。実ブラウザPDFの1ページ成立・背景色は環境制約により未確認です。
- 通常印刷の範囲は当期の方式別比較です。入力画面・更新履歴・4期累計・追加費用・展開した計算過程は含みません。顧客用印刷・コピー・CSVは従来の別出力を維持し、所内原価・相談メモ・元CSV個別情報を比較帳票へ追加しません。
- r28当初の表・印刷変更では税額算式・丸め・CSV導線を変更していません。その後のF01〜F05修正では選択可否・入力検証・CSV由来・既知0円の扱いを改めています。実際の見た目とPDF／プリンターでのページ数は未確認です。検証記録：`docs/current-rate-comparison-verification.md`、`docs/r28-fix-verification.md`。

- 高額特定資産等の金額・区分による判定補助と将来期制限
- 税率別課税標準、国税・地方税の申告書段階の端数処理
- 通常画面を維持し、必要時だけ追加項目を開く詳細試算モード

## r11の主な対応

- 0円を入力済みとして保持し、空欄・無効文字列・禁止された負数と区別
- 売上0円・仕入ありの本則課税による還付試算
- 簡易課税の1事業・2事業の75％特例
- 適用要件を「確認済み候補」「要確認」「適用不可」に三値化
- 未確認方式を順位から除外し、「最有利」の断定を抑制
- 本則控除率を未確認・100％確認済み・概算率入力に区分
- 4期比較を「各期単独比較」と明確化
- 将来期の免税事業者仕入控除率を期間内均等発生の日数按分で計算
- 入力値の端末保存を初期オフの任意選択へ変更
- コピー・CSV・印刷へ版数、前提条件、未確認事項を出力
