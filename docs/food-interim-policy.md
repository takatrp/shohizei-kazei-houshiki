## 共通結果とUI接続

`food-interim-comparison.js` はDOMに依存せず、ブラウザでは `ShohizeiFoodInterimComparison` を提供します。通常 `InterimTax.plan()` の入力を `ordinaryInput` へ、共有の実際前期と内訳を `priorActual` へ渡します。

```js
const result = ShohizeiFoodInterimComparison.compare({
  ordinaryInput: {
    priorNationalTax: 1092000,
    priorStart: '2026-04-01', priorEnd: '2027-03-31',
    currentStart: '2027-04-01', currentEnd: '2028-03-31',
    entityType: 'corporation', periodShortening: 'none',
    corporateExtension: 'none', specialCircumstances: 'none', taxScenario: 'foodProposal'
  },
  priorActual: {
    source: 'actual', period: {start: '2026-04-01', end: '2027-03-31'},
    exactMethod: 'regular', nonTaxableSales: 0, adjustmentNational: 0,
    creditMethod: 'full',
    transactions: [
      {side:'sales', amount:32400000, originalRate:8, category:'food'},
      {side:'sales', amount:22000000, originalRate:10, category:'other'},
      {side:'purchases', amount:21600000, originalRate:8, category:'food', usage:'taxableOnly', creditRatio:1},
      {side:'purchases', amount:15400000, originalRate:10, category:'other', usage:'taxableOnly', creditRatio:1}
    ]
  },
  annualTax: {A:1400000, B:700000},
  selection: {A:'ordinary', B:'ordinary'},
  manualPlanned: {A:false, B:false}
});
```

`ordinary` と `special` は通常planと同じ回別・国税地方税別構造です。`differences` は両方式の回別差額、`retainedDuringPeriod` は当期中の期限に限った通常支払額−特例支払額です。増額の場合は負額を表示します。`settlements.A/B.ordinary/special` は同一の年税額から中間納付を控除した確定納付・還付で、精算一致フラグを持ちます。

`selection` を省略すると両案とも通常planを維持します。A/B別の明示的な特例選択だけを `selectedPlans` に反映します。既存手入力予定があれば `manualPlanned` を指定し、自動額で上書きしません。画面・コピー・CSV・印刷にはこの同じ返値を使います。

## 不足資料・互換性・残る制限

- 当期入力やSTEP3代理額は実前期内訳として扱いません。内訳期間は共有前期期間と完全一致が必要です。
- 旧保存 `priorTaxMethod='regular'` は分類のまま残し、正確な前期方式を自動推定しません。`exactMethod` が未確認なら通常中間納付だけ継続します。
- 元税率・食品／その他・税込金額が必要です。一般課税の仕入は用途・控除割合、非課税売上・国税調整・控除方法が必要です。空欄を明示0円へ変換しません。
- 食品は前期の税抜取引額を保持して1％／8％に読み替えます。新聞8％・標準10％を食品へ変更しません。簡易課税は法令上の事業区分別に既存エンジンの75％判定を使います。
- 一般課税の通常返品は元税率・元課税状況の確認があれば別控除できます。元取引不明の調整、複雑な簡易課税等の返品、一般課税で必要となる輸入の特例税率再計算は不足区分を示して特例額のみ未算定にします。簡易課税・2割・3割の実仕入は税額算定に使用しません。通常額・当期税額・他の資金差は停止しません。負額を0円として再計算しません。
- 短期、課税期間短縮、前期の途中更正等は既存通常planの制限を保持します。
- 複雑な申告書の1円単位の途中端数配賦は正式様式等の確認対象です。中間比較は政策参考値であり、申告書作成システムにはしません。
- 保存対象は数値と適用条件のみ。CSV原文・摘要・取引先を追加保存する処理はありません。

### 共有前期CSVの再利用

`prior-actual-evidence.js` の `ShohizeiPriorActualEvidence.fromSharedCsv()` は、共有前期と正式CSV期間・原文ID・全月網羅・方式が使用する現在行と月別税区分総額の対応を検証します。使用する側が全て一致し、その食品区分が既存欄で照合済みなら、現在のCSV行から `priorActual` を構築して上記 `compare()` に渡せます。食品・その他の4金額を再入力する必要はありません。

入力は `priorFacts`（共有前期状態）、`csvSource`（共有CSV状態）、`currentSourceId`、`rows`、`monthlyGroups`、`actualOnePercentEntries`、`foodSalesConfirmed`、`foodPurchasesConfirmed`、`exactMethod`、`creditMethod`、`adjustmentNational` です。食品確認は既存の `confirmed`／`none` 又は明示trueを受け付けます。`none` と食品額が矛盾する場合は再利用しません。旧保存から正確な前期方式を推定しません。

既存CSV取込由来のゼロ根拠は `knownNonTaxableZero` で引き継げます。CSVに仕入内訳がない場合は、明示ゼロの根拠を持つときだけ `knownPurchaseZero` を指定します。方式で使用する金額・元税率・用途・控除割合はCSVの現在行を使い、手入力行や4金額の仮定からは前期実績を作りません。簡易課税・2割・3割は実仕入を使用しないため、仕入行・仕入月別集計・仕入1％サイドカーやその食品確認は前期税額の停止条件にせず、売上側だけを検証して再利用します。不使用の仕入入力・確認は削除又は確認済みに変更しません。元月額との一致が保たれた `csv-edited` 行の食品内数補足は利用できます。

元課税状況不明の返品、未対応の負額・輸入、不明日付・別期間・別資料・現在行の未対応変更は、通常納付を止めず、再利用する前期証拠だけ不足にします。課税区分11の元税率・元課税状況を照合済みなら、返品・取消を分けて再利用します。明示1％は実績サイドカーの日付・元税率・食品確認と月額を照合し、8％予測と重ねて計上しません。

### 返品APIとCSVの対応

`priorActual.transactions` の返品は `transactionKind:'return'`、`originalRate`、`originalTaxableState:'taxable'|'exempt'|'unknown'` を指定します。元課税状況unknown又は欠落なら(b)で未算定です。課税区分11等の元入力は `sourceTaxCode:'11'` として保持できます。

`amountDirection:'return'`（既定）の金額は、正が返還、負が返還取消です。`amountDirection:'signed'` は元CSVサイドカー等の既に税額方向へ署名済みの金額です。両方を反転しません。CSV区分11は元rowの`amount`を一度反転して月別集計と照合し、元税率・元課税状況の確認済みmetadataがある行だけ再利用します。明示1％返品は元取引日と元税率の既存検証も必要です。

一般課税の独立検算: 元政策再計算額は国税546,000円・地方154,000円。元8％税込返還1,080,000円の返還国税62,400円を別控除すると国税483,600円・地方136,400円、計620,000円です。中間1回は国税241,800円・地方68,200円、計310,000円。返還取消は逆に計780,000円になります。元売上時の免税確認なら控除なしで元政策額700,000円を維持します。

関連自動テストは55件成功（通常中間7・食品中間33・共有証拠15）。UI・保存・出力の追加連携は親の統合検証記録を優先します。


### 単一業種の簡易課税等を(a)から(c)へ絞り直した追加確認

NTA6505（2026-04-01現在）の単一業種の原則算式、Q&A問3-6の本文18〜19頁の返還税額控除後の計算及び同問の2割・3割にも同様という説明を再照合しました。この範囲は既知の算式で計算できるため、返品があることだけを理由に一律未算定にしません。

`food-interim-comparison.js` は国税段階で返還を分けた後、既存 `calculateSimplifiedTax`／`calculateSpecialMethodAmount` に同じ符号付き基礎を渡して検証します。1％食品部分は売上国税から元1％の返還国税を差し引いた同額控除で、負額も維持します。旧8％・10％返品は食品1％の同額控除へ混ぜず、食品以外の差引税額へ反映します。その他部分が非負で単一業種なら、既知のみなし率から控除を計算して共通の国税・地方税端数処理へ接続します。終了時の再計算では食品同額控除を使いません。

独立検算: 既存例の食品税抜売上3,000万円を政策1％とし、その他10％税抜売上2,000万円、旧8％の税込返品1,080万円（元税抜1,000万円）を追加します。その他の差引税額は200万円−80万円＝120万円、第二種/2割の負担は24万円、3割は36万円です。元1％税込返品1,010万円の場合は食品同額控除が減るだけで、その他10％税額200万円の負担は40万円/60万円を維持します。食品返還が食品売上を超える4,040万円でも符号付き同額控除が相殺されます。旧8％返品取消なら第二種負担56万円です。終了時は、食品2,400,000円＋その他2,000,000円−元1％返品100,000円＝4,300,000円に第二種負担20％を適用して860,000円となります。

これらは政策参考値です。複数業種の返還・75％・食品以外の負基礎など、当作業で必要な一次根拠を確定できていない複合ケースに限り(a)を残します。元課税状態や事業区分等が不明なものは(b)です。入力の不足と制度調査の不足を混同しません。


### 査読による丸め順と依存範囲の追加修正

国税段階の丸めは返品有無で分岐させません。食品元8％税込100,001円、その他10％税込119,932円、第二種という査読例は、食品国税`floor(92,000×0.78％)=717`、その他国税`109,000×7.8％=8,502`です。簡易/2割の控除は`717+floor(8,502×80％)=7,518`、差引国税1,701円→1,700円、地方400円、計2,100円。3割は控除6,668円、差引国税2,551円→2,500円、地方700円、計3,200円です。国税0円となる旧8％の1円返品を加えても、この結果が変わらないことを確認しました。

旧枝では丸め前の総税額から作った控除割合を、丸め後の国税総額に再乗算していたため、上記の簡易/2割が2,000円になっていました。今回は各税額から国税控除を1円単位で計算してから差引・国税100円・地方100円を順に処理し、現行の`tax-return-engine.js`の国税段階の不変条件と照合しました。

複数業種の返品なし通常案件も、既知の付表5-3の税率別国税基礎、事業別国税の配賦基礎、みなし控除の1円未満切捨て、75％候補選択を同じ国税段階に接続しました。候補の該当性は既存`calculateSimplifiedTax`を再利用し、税率を通じて同じ候補を選択します。第二種/第四種の各税込1,100,660円（10％）では、国税計算基礎156,078円、事業別国税合計156,092円、控除109,253円、年税額60,000円を現行付表エンジンとも照合しました。食品を除いた第二種売上割合80％のQ&A例も年税額200,000円を維持します。

実仕入を使わない簡易・2割・3割に対し、仕入の負額・輸入区分不明・食品区分未確認を理由に売上基礎の税額まで止めないよう、計算関数と共有CSV証拠の両方で依存範囲を限定しました。証拠には`usedSides`と`foodClassificationVerifiedSides`を保持し、使っていない仕入を確認済みにはしません。一般課税では引き続き仕入側の必要資料を要求し、不正な売上や未知のsideも無条件には無視しません。
