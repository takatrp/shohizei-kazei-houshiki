# r36.0.2 中間納付・4金額入力の軽量改善

2026-10-24。起点mainはr36.0.1 `ad0df3a48fafebc09ee8454ae0c62880e92505f6`。独立ブランチ `codex/lightweight-interim-copy-20261024` で実装・検証した。版数はr36.0.2 / package36.0.2。以下は製品の修正範囲と検証記録。

## 確認した原因と対応

| 要求 | 旧挙動と最小修正 |
|---|---|
| 現行税率と利用予定 | 食品特例の接続がシナリオに依存せず、比較オブジェクトがあるだけで「明示した利用予定」と表示していた。現行税率では比較計算・特例欄・特例出力を接続しない。食品側は比較可能性、利用指定、資金繰りへの反映を分け、通常納付だけなら見出し・コピー・CSV・印刷も通常納付とする。選択前でも食品側の入口を残す。 |
| A/B比較軸 | 税率比較のAにも保存済み特例指定が渡る一方、方式比較は選択結果を月次予定に接続していなかった。8％維持Aは通常納付へ固定し、画面のA欄も固定表示。1％世界の方式比較は両案を独立指定し、各案の予定を月次エンジンへ渡す。方式別の当期年税額で精算を照合する。 |
| 飲食店4金額 | 汎用「食品売上」だけでは店内飲食を含める誤解が生じ、現行税率でも政策試算の案内だった。既存欄へ軽減8％/10％を明記し、既存説明へテイクアウト・物販/店内飲食・酒類の短い例を表示。現行税率と政策試算の案内を切り替える。 |
| 資料基準日 | `APP_META.proposalBasisDate` は製品の表示・計算では参照されていない（定義のみ。検証スクリプトでは値を確認）。`2026-09-15` は制度資料の基準日で、確認日を示す `proposalBasisLabel` の2026-10-24とは別概念。未使用値による誤表示はなく、日付・ラベルとも変更しない。新しい制度調査や見せかけの確認日更新は行っていない。 |

税額の算式・税計算エンジンは変更しない。年税額の比較と、納付時期による一時的な資金差は分離したまま。別の前期仮定、STEP3代理値、資料不足、手入力予定は既存の制限を維持し、未算定を0円や特例利用可能へ補完しない。旧A指定は保存値を消さず、比較軸に応じた適用境界で無効化する。保存形式の変更はない。
